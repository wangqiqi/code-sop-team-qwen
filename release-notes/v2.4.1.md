## 这个版本改了什么

### 修：`test_21` 在 GitHub Windows runner 上误判

CI 的 `TEMP` 是 8.3 短路径（`C:\Users\RUNNER~1\AppData\Local\Temp\...`），而闸门上报的是长路径（`runneradmin`）。原用例直接比字符串，必然失败——是测试写法不够可移植，不是闸门逻辑有问题。

现在改成用 `os.path.samefile()` 比较文件系统身份，短名、长名、大小写差异都能正确判定。已在本地用 8.3 短路径复现并验证通过。

### 新增：自动化校验与发布

- `tools/validate_kit.py` — 套件结构校验（两份清单一致、双语字段齐全、每个 `SKILL.md` 的 frontmatter、`icon.png`、无残留文件、体积上限）
- `tools/build_kit.py` — 可复现打包（固定时间戳与权限，同一份源码永远同一个 SHA-256）
- `tools/check_reproducible.py` — 连打两次比对哈希
- `.github/workflows/ci.yml` — push/PR 触发，Ubuntu 22.04/py3.8、Ubuntu/py3.12、Windows/py3.12 三腿跑 43 用例 + 结构校验 + 打包 + 复现性检查
- `.github/workflows/release.yml` — 推 `v*` tag 触发：校验通过且 tag 与清单 `version` 一致才打包，自检 ZIP 内部结构后自动建 Release 并附包

产物从"手工打包"变成"CI 构建 + 可复现校验"，下载页的大小与 SHA-256 由工作流自动写入说明末尾。
